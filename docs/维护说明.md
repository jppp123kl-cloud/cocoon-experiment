# 页面怎么维护

## 两个独立入口

- `index.html`：沿用原版四幕动画的中期展示，去掉讲稿、提词器、计时器和答辩问答。保留原文查看、深浅主题、受试编号切换、干预轮次切换和结果曲线。
- `assistant.html`：独立的助手体验页。保留原来的模式选择、话题输入、分步分析、报告、认知镜和自检流程。

展示页上的“体验破茧助手”会在新标签页打开助手。助手没有混入实验展示栏目。

## 修改入口

根目录两页由 `scripts/build_midterm_views.py` 从原始网页生成，执行 `python3 scripts/build_midterm_views.py` 即可重建。

- `web/showcase-polish.css`：展示页外围排版与窄屏适配，四幕动画本体保留原样。
- `web/assistant-polish.css`：助手的配色、字体、留白和卡片样式。
- `web/assistant-polish.js`：让原有可点击卡片支持键盘操作。
- `scripts/build_midterm_views.py`：删减展示辅助栏目，替换界面文字。助手原来的内嵌脚本保持不变。

不要直接修改生成后的根目录 HTML，否则重建时会覆盖。用于校验的原助手网页、压缩包、来源记录及 `experiment/` 历史记录继续保留。已删除两份不参与运行的展开文档，详见 [文件清理记录](文件清理记录.md)。实验数据和实际使用的提示词不变。旧展示生成器 `cocoon/showcase.py` 仍用于重建历史版本。

## 模型模式的实际行为

本次恢复原来的模型调用逻辑：直接打开本地文件时无法调用模型；通过本地服务打开后，还需要模型服务允许浏览器连接。部分请求失败会退回模拟内容。示例和模型生成的链接都不能当作已经核查的事实来源。

## 检查方式

安装有 Playwright（浏览器自动检查工具）的环境中，运行 `node tests/check_midterm_ui.cjs`。可通过 `COCOON_BROWSER` 指定浏览器位置；通过 `COCOON_SCREENSHOT_DIR` 指定截图目录。

检查涵盖：四幕图形和动画与原版一致（仅调整最后一幕的两个辅助链接）、助手原有脚本一致；克隆与八轮染色、受试和轮次切换、指标与主题切换、原文与中期进展展开；助手模式、自检、分析、认知镜、重置、停止及不同屏幕宽度。

这些是界面检查，不会调用付费模型，也不替代研究实验验证。
